# 洞穴照明累积暴露与藻类停光复核台

洞穴样点的照明暴露登记与停光复核闭环管理。

## 业务规则

- 每样点同时只允许一条未结束照明记录，重复或并发开启沿用首次记录。
- 每条记录登记照度（勒克斯）、时长（小时）与操作员。
- 累计照度时长超过 1800 勒克斯小时，或连续照明超过 10 小时，自动转待复核；期间禁止开启新照明。
- 复光条件：换人连续两次复测回落（藻类覆盖率下降），两次间隔不少于 12 小时。
- 更正原记录会使已有复测与复光结论失效，并按更正后的事实重新计算。
- 复光通过后进入新一轮暴露周期，累计照度时长重新起算。

## 结构

规则、存储、页面分离：

- `rules.js` — 业务规则（纯函数：超限判定、状态重算、复测/复光/更正守卫）
- `store.js` — 存储（`data/db.json`，读写串行化，并发请求不互相覆盖）
- `server.js` — HTTP 接口层（仅做请求映射）
- `project.config.js` — 页面配置（视图、表单、动作及可见条件）
- `public/` — 页面（配置驱动渲染）

派生状态（记录状态、样点状态、累计照度时长）由 `rules.js` 根据既有事实重算并落盘，
每次读取前也会幂等重算，因此列表、统计与履历在刷新后保持一致。

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/db` | 全量数据（读取前重算派生状态） |
| POST | `/api/sites` | 新增样点 |
| POST | `/api/exposures` | 开启照明（重复/并发沿用首次记录） |
| POST | `/api/exposures/:id/end` | 结束照明（登记时长） |
| POST | `/api/exposures/:id/recheck` | 登记复测（换人、回落、间隔 12 小时） |
| POST | `/api/exposures/:id/resume` | 确认复光（进入新一轮周期） |
| PATCH | `/api/exposures/:id` | 更正记录（旧结论失效重算） |
