# 洞穴照明累积暴露与藻类停光复核台

按样点管控洞穴照明开停，超限自动停光复核，复光须换人复测回落。

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

数据保存在 `data/db.json`（可用环境变量 `DB_FILE` 覆盖），后续可以继续增量迭代。

## 分层

- `rules.js` —— 规则层：限值常量、暴露计算、超限判定、复测回落链、复光判定、更正失效重算，全部为纯函数，不做 IO。
- `storage.js` —— 存储层：`db.json` 读取与串行化写入（promise 队列 + 临时文件替换），并发开灯也能守住"一样点一记录"。
- `server.js` —— HTTP 层：只做请求/响应适配。
- `project.config.js` + `public/` —— 页面层：展示配置与前端，限值经 `/api/config` 从规则层下发，页面不实现业务规则。

## 业务规则

- 每样点同时只允许一条未结束照明记录；重复或并发开灯沿用首次记录（返回已有记录，不新建）。
- 记录照度（lux）、时长（开始/结束时间推算）与操作员。
- 结束照明时判定：本周期累计照度时长 > 1800 勒克斯时，或单次连续照明 > 10 小时 → 转停光待复核，期间禁止该样点开新照明。
- 复光条件：换人（复测员 ≠ 原照明操作员）连续 2 次复测回落（藻类指数逐次下降），且相邻两次间隔 ≥ 12 小时；满足后自动放行，样点恢复可照明，累计周期重新起算。
- 更正原照明记录（照度、时间、操作员、停光指数）后，该记录全部旧复测结论失效，状态按当前数据重算。
- 列表、统计与履历均由同一份持久化状态派生，刷新后一致。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/config` | 展示配置 + 规则限值 |
| GET | `/api/db` | 全量数据（含派生字段：时长、暴露、样点状态、复测进度） |
| POST | `/api/sites` | 新增样点 |
| POST | `/api/lightings` | 开灯（重复/并发返回 `reused: true` 的首次记录） |
| POST | `/api/lightings/:id/end` | 结束照明（登记停光藻类指数，超限转待复核） |
| POST | `/api/lightings/:id/rechecks` | 登记复测（满足条件自动复光放行） |
| POST | `/api/lightings/:id/correct` | 更正原记录（旧结论失效重算） |
